直接给结论：租，但不用 SSH，也不用整机月付。你现在只是要「编译 → 签名 → 上传 TestFlight」，选 MacinCloud 按小时（PAYG by Hours） 最省：$1.25/小时，25 小时额度约 $31.25（≈¥225），用完就停；镜像选 macOS Tahoe 26.6+ / Xcode 26.6，直接满足 2026-04-28 起的上传要求。

三个误区先纠正：（后端公网化已单独展开 → 后端部署到 app.kqi.ink）① SSH 不是必须的——云 Mac 给的是 RDP 图形桌面，在里面开「终端」就能跑全部命令，MacinCloud 加购 SSH 还要额外加钱；② 真 iPhone 不用插线——云 Mac 在机房，USB 连不到你的手机，上传 TestFlight 后手机无线安装测试；③ 云 Mac 编译成功 ≠ 手机能拉到配置——后端必须公网 HTTPS，见第 5 节，这是最容易踩的坑。

3. 连上之后，7 步走完

1
收开通邮件，拿到 RDP 主机 / 用户名 / 密码。Windows 用「远程桌面连接」(mstsc) 或 Microsoft Remote Desktop 连上，首次改临时密码。
2
传工程：把整个 channel-switch/ 打成 zip，用 MacinCloud 上传工具 / OneDrive / 网盘 / Git 传到云 Mac 并解压。别用剪贴板拖大目录。
3
跑初始化（无 root 也能装 xcodegen）：
cd channel-switch/xcode && ./scripts/cloud_mac_setup.sh
它会查 Xcode≥26 / iOS 26 SDK、把 XcodeGen 装到 ~/.local/bin、检查工程与凭据、提示后端公网化。
4
登录开发者账号：打开 Xcode → Settings → Accounts，登录已付费的 Apple Developer 账号（自动签名需要；Agent/Admin 权限才能自动建 Distribution 证书）。
5
填 3 个值：两份 xcconfig 的 MZH_TEAM_ID、Config-Release.xcconfig 的 HTTPS 配置域名（见第 5 节）；.p8 放到 ~/.appstoreconnect/private_keys/AuthKey_<KeyID>.p8。
6
编译上传：./scripts/preflight.sh → xcodegen generate --spec project.yml → ./scripts/build.sh → ./scripts/upload.sh。首次 Swift 编译报错把完整日志贴回来，我按行修。
7
真机测试：iPhone 装 TestFlight，等构建 Processing 完（几分钟），安装后用后台「⑦ 百度推广 API 归因对接」模拟 bbdd1 点击，验开屏 → 试看 → 充值闭环、退出保留进度、登录后 1s 弹充值、账号注销。不需要把手机插到任何电脑上。

4. 凭据在共享 Mac 上的处置

MacinCloud 的 PAYG / Managed 是共享物理 Mac 上的用户账号，没有 root，也不由你独占系统。做构建没问题，但凭据要按可撤销的方式用：

  • 上传只用 App Store Connect API Key（Issuer ID / Key ID / .p8），不要拿主账号密码去脚本里跑；
  • 签名优先用「Xcode 登录 + 自动签名」，或导入一份单独的 Distribution 证书；
  • 收工前：Xcode → Accounts 退出登录、删掉机器上的 .p8、在 App Store Connect 撤销这次用的 Key（随时可再建）；
  • 不要在托管镜像的钥匙串里长期保存密码；要长期用就换第 1 节的整机方案（root + 独占钥匙串）。

5. 最容易踩的坑：云 Mac 编译好了，手机却一直合规态

Archive 只是把代码编成 IPA，编译期不请求配置服务；App 在手机上运行才去拉 /v1/config。你现在的后端跑在 Windows 的 192.168.11.14:8790，云 Mac 和手机都访问不到这个局域网地址，于是客户端按设计回落 normal，看不到渠道闭环。正式方案已定：复用你已有的 https://app.kqi.ink 挂 /mzh/ 子路径，部署包与一键脚本已备好，见 后端部署到 app.kqi.ink 操作手册。三种可选状态：

方式怎么做
① 正式：上公网
提审必须		已于 2026-11-25 17:21 部署完成并线上验证 15/15 PASS：复用现有域名与证书，后端挂在 https://app.kqi.ink/mzh，systemd 常驻 + nginx 反代 + 后台 Basic Auth；/mzh/health 与 /mzh/demo 实测 200，/mzh/admin 401→认证后 200，原有 /site 不受影响。两份 xcconfig 的 CONFIG_BASE_URL 均为 https:/$()/app.kqi.ink/mzh，云 Mac / TestFlight 真机可直接连。详见 部署手册 与 上线信息页。
② 临时：穿透本机

③ 不改也能测H5 Demo http://192.168.11.14:8790/demo 与后台 /admin 仍在同一局域网，手机连家里 Wi-Fi 就能验全部交互逻辑；只有原生 IPA 才需要公网地址。
xcconfig 写法提醒：// 在 xcconfig 里是注释，URL 必须写成 https:/$()/config.example.com（Xcode 把 $() 展开为空，得到 https://config.example.com）。cloud_mac_setup.sh 与 preflight.sh 会检查这一项并对局域网地址告警。

6. 零租金备选：GitHub Actions（不租任何 Mac）

已经写好 .github/workflows/ios-testflight.yml，用 runs-on: macos-26（该镜像默认 Xcode 26.6 / iOS 26 SDK）。把工程 push 到 GitHub，在仓库 Settings → Secrets 里配好下列变量，手动触发即可 Archive + 导出 IPA + 上传 TestFlight：

MZH_TEAM_ID          Team ID（10 位）
MZH_BUNDLE_ID        com.mizhenhe.player
CONFIG_HOST          配置域名，不带 https://，如 config.example.com
ASC_KEY_ID           App Store Connect API Key ID
ASC_ISSUER_ID        Issuer ID
ASC_P8_BASE64        .p8 文件的 base64
CERT_P12_BASE64      Apple Distribution 证书 .p12 的 base64
CERT_PASSWORD        .p12 密码
PROFILE_BASE64       App Store 描述文件 .mobileprovision 的 base64
PROFILE_UUID         描述文件 UUID

CI 上没有 Xcode 账号交互登录，所以 workflow 走手动签名（import_signing.sh 建临时钥匙串 → 导入证书和描述文件 → CODE_SIGN_STYLE=Manual）。公开仓库标准 runner 免费；私有仓库 macOS 分钟按 10× 消耗免费额度，GitHub Free 每月约 194 分钟 macOS，够 25–35 次构建。这条路线省掉租金，代价是每次改动要 push 一次、反馈比 RDP 里直接改慢一点。
