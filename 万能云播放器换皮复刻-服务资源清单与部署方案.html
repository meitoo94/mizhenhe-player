三、需要什么服务资源

3.1 你已有的四类资源 → 直接复用映射

按你说的「本地有服务器、后台、网站、App，在云上跑」，以及截图里「播放器」空间下 主程序 / 代码助手1号 的分工，交付也按这两块切开：主程序 = server/app.py + SwiftUI 客户端；代码助手1号 = 皮肤配置、自检脚本、界面原型、素材与文案。

你已有本方案里承担什么要补的改造
服务器（云主机 / 云行这类 IDC）跑配置 API、归因、订单、支付回调、落地页、法务静态站、日志装 Python 3（零依赖即可跑）、反向代理 + HTTPS、进程守护（systemd / supervisor）、出站放行 api-adservices.apple.com
后台（管理端）渠道表、灰度、安装时长、时间窗、全局开关、判定日志、订单与会员查询把 /admin/channels、/admin/logs 接进现有后台并加鉴权 + 只允许内网；enabled=false 做成一键全量关
网站（已备案域名）隐私政策 / 用户协议 / 会员协议 / 技术支持页、售后联系 URL、落地页域名补 4 份静态文档 + 页脚备案号 + 独立子域；确认备案主体与网站内容类别一致
App（iOS 工程）合规态 + 付费墙两套 UI、归因、验签、Keychain接本仓库 7 个 Swift 文件；构建时注入 SkinTabs / SkinHeadline；换 ChannelAttribution.baseURL

「云行」检索到两类同名主体：北京云行互联（yxclouds.com，持 IDC / CDN / ISP 牌照）与云行科技（电力物联网）。这里按「你自己的云主机托管」处理；如果指的是前者，对象存储、CDN、备案服务码可以在同一平台直接开，下面 3.2 的 ③④ 项就能省掉采购。

3.5 容量与成本推导（数字来源标清）

本次实测：单次 paywall 配置响应 4,949 字节、normal 响应 2,631 字节（127.0.0.1:8789 真实返回）。按 1 万日活、每台每天 2 次冷启动拉配置算：

  • 配置 API：1 万 × 2 × 4.9 KB ≈ 98 MB/天，峰值 QPS 远小于 50，2C4G + 5Mbps 绰绰有余 —— API 不是瓶颈。
  • CDN：竖屏 15s / 720×1280 / ~1.5 Mbps ≈ 2–4 MB 一次播放；1 万次日播放 ≈ 30 GB/天 ≈ 900 GB/月 —— 流量成本几乎全在视频。
  • 存储：10 条素材 × 3 码率 × 3 MB + 封面 ≈ 100 MB，100GB 桶足够放很多套皮肤素材。
  • 数据库：点击 + 决策 + 订单 + 登录约 6–7 张表，日增 10 万行量级，按月归档决策日志即可。

3.8 部署顺序

  1. 主域下加 5 条子域解析，申请 DV 证书，大陆节点完成备案（可与后续并行，周期最长）。
  2. 把 server/app.py 布到现有服务器，systemd 托管，反向代理 HTTPS；SWITCH_SECRET 走环境变量 / KMS。
  3. 把内存状态换成数据库表（渠道、点击、归因、订单、会员、登录、决策），Redis 接幂等与限流。
  4. 法务站 4 份静态页上线，页脚挂备案号；App Store Connect 填隐私政策 URL / 支持 URL。
  5. 对象存储 + CDN 开起来，15s 试看素材转 3 码率 + 封面，配签名 URL；替换 trial.video_url / poster_url。
  6. 支付通道签约，/v1/pay/notify 接支付宝异步通知并验签，对账脚本跑通。
  7. 现有后台接入 /admin/channels 与 /admin/logs，鉴权 + 内网，做一键全量关。
  8. iOS 工程接 7 个 Swift 文件，构建时注入 SkinTabs / SkinHeadline，baseURL 指向 cfg. 子域。
  9. macOS CI 跑 Archive / 签名 / 上传 TestFlight，真机跑一遍完整链路。
  10. 提审；上线后按渠道灰度从 5% → 30% → 全量，观察决策日志与订单成功率。
