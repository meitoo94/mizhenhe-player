百度推广 API 归因对接方案

渠道号不是剪贴板给的：百度回传「点击 IP / 设备号」→ 我方后台定义渠道号 bbdd1 → 安装首启按 IP / 设备号绑定 → 按该渠道展示配置下发。
本页是补齐的研究与对接说明，配套代码已落地并跑通端到端自检。
纠正上一版的理解偏差：之前把主链路做成了「落地页写剪贴板 token → App 首启读剪贴板 → 换渠道号」。 你实际要的是服务端侧归因：包投在百度推广，你们与百度后台已有 API 归因对接，百度把「哪些 IP / 设备号是从广告点击进来的」给到我方后台； 安装后我方后台一看这个 IP 就知道来自百度，于是按我们自定义的渠道号（例如 bbdd1）给这台设备下发该渠道自己配置的展示。 现在剪贴板已从判定链路中移除，只保留调试打点，不再是渠道号来源。

1. 完整时序

STEP 1
百度广告点击
用户在百度推广点广告。百度侧记录 click_id、点击出口 IP、设备标识、计划 ID、点击时间。
→
STEP 2
API 归因回传
百度后台通过你们已对接的 API，把点击明细回传到我方 POST /v1/attribution/baidu/callback（也可由我方定时拉取后批量灌入 clicks[]）。
→
STEP 3
定义渠道号
后台按「百度计划ID → 我方渠道号」映射，例如 baidu_plan_a → bbdd1； 渠道号完全由我方命名，可随时加 bbdd2、按投放计划拆多套展示。
→
STEP 4
安装首启
App 装上后第一次启动，只上报设备上下文（idfv / idfa / CAID、机型、时区语言等）， 不带渠道号；服务端记录这次请求的出口 IP。
→
STEP 5
服务端匹配 + 绑定
/v1/attribution/resolve 用「设备号精确 > 出口 IP + 多特征 > 纯 IP」匹配点击库， 命中则把 bbdd1 写进设备绑定表并落盘。
→
STEP 6
按渠道展示
/v1/config 自动按绑定渠道下发；bbdd1 自己那套栏目 / 模块 / 套餐 / 倒计时生效。 未命中一律 organic 合规态。

2. 回传字段（我方接收端点）

百度侧具体字段名以你们已有的对接文档为准；我方接收端点做了兼容，设备号字段任选其一即可， 渠道号优先取回传里的 channel，没带就按 plan_id 查映射表。

字段含义是否必需我方处理
click_id百度侧点击唯一 ID必需幂等去重键，重复回传只累计 duplicates，不新增记录
ip点击时的出口 IP必需（缺省取请求 IP）首启时与 App 请求出口 IP 比对；支持 /24 同段弱匹配
idfa / caid / device_id / oaid / idfv设备号（任一）强烈建议只以加盐 SHA-256 前 24 位落盘，不存明文；精确匹配优先级最高
plan_id百度投放计划/单元 ID二选一查 channel_map 得到我方渠道号
channel直接指定我方渠道号二选一例如 bbdd1，优先级高于 plan_id 映射
ts点击时间戳（秒）可选缺省用服务器时间；超出 window_seconds 的点击不再参与匹配
ua / model / tz / lang / screen辅助指纹可选纯 IP 不够时用于加权；严格模式要求至少 2 项命中
_sigHMAC-SHA256 签名生产必需设置环境变量 BAIDU_API_SECRET 后强制校验，防止伪造回传

可运行示例

# 单条回传（本机 8790 服务）
curl -X POST http://127.0.0.1:8790/v1/attribution/baidu/callback \
  -H "Content-Type: application/json" \
  -d '{"click_id":"BAIDU-CLK-001","plan_id":"baidu_plan_a",
       "ip":"203.0.113.77","device_id":"DEVICE-BAIDU-001",
       "ua":"iPhone","model":"iPhone","tz":"Asia/Shanghai",
       "lang":"zh-CN","screen":"1170x2532@3"}'

# 批量（拉取模式：把百度给的一批点击一次性灌入）
curl -X POST http://127.0.0.1:8790/v1/attribution/baidu/callback \
  -H "Content-Type: application/json" \
  -d '{"clicks":[{"click_id":"A1","plan_id":"baidu_plan_a","ip":"203.0.113.77"},
                  {"click_id":"A2","channel":"bbdd1","ip":"203.0.113.78","idfa":"XXXX"}]}'

# App 首启（客户端不传渠道号）
curl -X POST http://127.0.0.1:8790/v1/attribution/resolve \
  -H "Content-Type: application/json" \
  -d '{"idfv":"IDFV-XXX","device_id":"DEVICE-BAIDU-001","ip":"203.0.113.77","country":"cn"}'
# → {"channel":"bbdd1","confidence":1.0,"method":"device_exact","bound":true,...}

# 配置下发（服务端自动按绑定解析渠道）
curl -X POST http://127.0.0.1:8790/v1/config \
  -H "Content-Type: application/json" \
  -d '{"idfv":"IDFV-XXX","auto_attribution":true,"country":"cn"}'

3. 匹配算法与防误判

优先级条件置信度方法名结果
1设备号哈希精确相等（IDFA / CAID / device_id / OAID / idfv）1.00device_exact直接绑定渠道
2出口 IP 精确相等 + 机型 / 时区 / 语言 / 屏幕 / UA 中命中 ≥1 项 + 时间窗内≥0.65ip_plus_fingerprint达到 min_confidence 即绑定
3只有「后台知道这个 IP 来自百度」0.65（可配）ip_from_partner_api默认允许命中（就是你说的那种情况）
4IP 只同 /24、无任何非 IP 特征，且开启严格模式≤0.30low_confidence回落 organic
5时间窗外 / 渠道不存在 / 全局熔断0no_match回落合规态

为什么默认允许纯 IP 命中、又保留严格模式开关：运营商 NAT / 公司 WiFi 下，同一个出口 IP 会有大量无关用户。 如果百度回传的 IP 粒度很粗，纯 IP 命中会把自然量误判成投放量。所以后台提供三档可调： allow_ip_only（默认开，贴合你的描述）、strict_mode（要求设备号或 ≥2 项非 IP 特征）、 window_seconds（默认 24h，点击久远就失效）。三者都在后台「⑦ 百度推广 API 归因对接」面板里即时生效。

审核与工程边界：未命中一律 organic；/admin/killswitch 一键全量回落； 绑定表可手动解绑、可一键清空；设备号只存哈希。命中后走付费墙这件事本身仍受 2.5.19（隐藏/休眠功能）、 3.1.1（数字内容必须走 IAP）约束 —— 归因方式换成 API 不改变这一层风险，详见 审核条款对照与检出面评估.html。

5. 隐私与设备标识

  • IDFA：iOS 14+ 必须经 AppTrackingTransparency 授权才能拿到有效值；未授权返回全零，代码里直接按 nil 处理，服务端退回 IP 匹配。
  • CAID：国内常用匿名标识，由第三方 SDK 提供；ChannelAttribution.caidIdentifier() 留了接入位，未接入返回 nil。
  • idfv：同一开发者账号下稳定，卸载重装会变。所以绑定表额外按出口 IP 哈希做兜底，设备号变了也能找回渠道。
  • 落盘：server/state/attribution.json 里只有加盐哈希、IP、渠道号、匹配方式、时间；不写明文设备号、手机号。
  • 生产鉴权：设置 BAIDU_API_SECRET 后，回传体必须带 _sig（对规范化 JSON 的 HMAC-SHA256），否则 403。

6. 真机验收（同 WiFi）

  1. 电脑打开 http://127.0.0.1:8790/admin → 拉到「⑦ 百度推广 API 归因对接」。
  2. 填「点击 IP / 设备号 / 百度计划ID」，渠道选 bbdd1，点「回传一条点击」→ 点击库出现一条记录。
  3. 复制面板里「② 手机首次启动验证」的链接（形如 http://192.168.11.14:8790/demo?auto=1&ip=...&dev=...），手机同 WiFi 打开。
  4. 手机 Demo 顶部调试栏显示 归因 bbdd1 · device_exact · conf 1，并进入 bbdd1 专属的 5s 开屏 / 20s 试看 / 2 档套餐。
  5. 点「解绑」再刷新验证链接，可重看「回传 → 首启匹配 → 绑定 → 下发」全过程；点「清空测试数据」回到全量合规态。
