① 渠道基础与守卫

渠道号由广告落地页写入，App 首启归因后存在 Keychain。这里控制它是否启用、走哪种形态、以及命中条件。

② 展示栏目（合规态）

按渠道控制哪些 Tab、首页分区、玩法卡片、云字幕与会员入口可见。没勾中的栏目不会出现在下发配置里。

③ 开屏 / 试看 / 支付 模块

这五个模块就是录屏里那套状态机。关掉某段，App 会直接跳过它；关掉「会员页」或「收银台」就不会出现支付界面。

④ 套餐展示与价格（已停用 · 不用再配）

原生 App 和 H5 演示的 VIP 档位，现在统一读 Yii2 后台 「支付相关管理 → 米帧盒VIP套餐」。 以后只在那一个栏目里改名称 / 折扣价 / 划线价 / 上下架 / 排序，保存后 App 刷新即生效，不用重新出包。
在这里勾选或改价不再影响任何一端；本区域编辑控件已隐藏，仅保留历史数据结构。 核对请开 渠道配置验证台。

⑦ 百度推广 API 归因对接（渠道号自动判定）

包放在百度推广，百度后台通过 API 回传「哪些 IP / 设备号 是从广告点击进来的」； 我方后台按「计划ID → 我方渠道号」建点击库（例如 baidu_plan_a → bbdd1）。 App 安装首启时服务端用出口 IP / 设备号匹配并绑定渠道号，之后按该渠道自己的展示配置下发。 不再依赖剪贴板。

⑧ 账号注销台账（App Store 5.1.1(v)）

支持登录的 App 必须能在 App 内删除账号。会员页 / 登录页 / 账户 Tab 三处都有入口， 服务端 POST /v1/account/delete 凭登录票据删除登录记录、会员权益、设备归因绑定； 交易流水只做去标识化，台账只留哈希与时间，不存手机号明文。 GET /admin/account/deletions 可导出核对。
—

⑨ 原后台接口接入（app.kqi.ink/site · PHP Yii2）

米帧盒的 /v1/* 已桥接到你原有 Yii2 后台的 /api/*： 注册进「用户管理」、下单进「充值记录」、档位读独立的「米帧盒VIP套餐」、支付走「支付配置」、 安装归因进「数据统计 / 百度转化回传」、注销同步「用户管理」。 写操作默认只放行新建测试渠道，跑量的 bbdd* / mt* / default 一个都不碰； 上游异常自动回落米帧盒本地实现。
